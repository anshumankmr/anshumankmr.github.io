"Hey Siri, Ask Claude" → "log two eggs and toast for breakfast" → the Claude app calls an MCP server on my Lambda → MyFitnessPal. It works, and the route there was more annoying than I expected.

What bit me along the way:

- **MyFitnessPal has no API.** The server rides a browser session cookie, and MFP *rotates* it: once a fresh one is issued, the old one stops working. I copied the cookie, it was dead within the hour. The fix was to treat the pasted cookie as a seed, and have the Lambda save the newest one to an SSM parameter and reload it on cold start.
- **The error message lied.** My account logs in by email, so the package needs `MFP_USERNAME` too. Without it every call failed with "session expired", which sent me chasing the cookie for an hour.
- **Lambda rejected my image.** GitHub's newer runners push OCI manifests with attestations, and Lambda won't take them. `docker buildx build --provenance=false --sbom=false` fixed it, and it only broke on a deploy that hadn't run in weeks.
- **I almost built a bypass token for Siri.** I didn't need to. The Claude iOS app has an "Ask Claude" intent, and it reaches the same connector, behind the same OAuth login.

I merged two small servers into one Lambda along the way. One connector now shows both the blog tools and the food tools.
